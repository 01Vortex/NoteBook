## 1. 基础概念

### 1.1 什么是渗透测试？

渗透测试 (Penetration Testing) 是一种通过模拟黑客攻击来评估系统安全性的方法。

**核心目标**:
- 发现系统安全漏洞
- 评估漏洞的实际危害
- 提供修复建议
- 验证安全防护措施

**与其他安全测试的区别**:

| 类型 | 目的 | 深度 | 破坏性 |
|------|------|------|--------|
| 漏洞扫描 | 发现已知漏洞 | 浅 | 低 |
| 渗透测试 | 验证漏洞可利用性 | 中 | 中 |
| 红队演练 | 模拟真实攻击 | 深 | 高 |
| 安全审计 | 合规性检查 | 全面 | 无 |

### 1.2 渗透测试类型

**按知识程度分类**:


```
黑盒测试 (Black Box)
  ├── 无任何内部信息
  ├── 模拟外部攻击者
  └── 最接近真实攻击场景

灰盒测试 (Gray Box)
  ├── 部分内部信息 (如普通用户权限)
  ├── 模拟内部人员攻击
  └── 平衡真实性和效率

白盒测试 (White Box)
  ├── 完整的系统信息
  ├── 包括源代码、架构文档
  └── 最全面的安全评估
```

**按测试目标分类**:
- 网络渗透测试
- Web 应用渗透测试
- 移动应用渗透测试
- 无线网络渗透测试
- 社会工程学测试
- 物理安全测试

### 1.3 渗透测试标准

**PTES (Penetration Testing Execution Standard)**:
- 前期交互 (Pre-engagement Interactions)
- 情报收集 (Intelligence Gathering)
- 威胁建模 (Threat Modeling)
- 漏洞分析 (Vulnerability Analysis)
- 漏洞利用 (Exploitation)
- 后渗透 (Post Exploitation)
- 报告 (Reporting)

**OWASP Testing Guide**:
- 专注于 Web 应用安全
- 提供详细的测试用例
- 定期更新漏洞类型

**OSSTMM (Open Source Security Testing Methodology Manual)**:
- 科学化的测试方法
- 量化安全评估
- 适用于各类系统

### 1.4 法律与道德

**⚠️ 重要提醒**:

```
未经授权的渗透测试是违法行为!

必须满足以下条件:
  ✅ 获得书面授权
  ✅ 明确测试范围
  ✅ 签署保密协议
  ✅ 购买责任保险
  ✅ 遵守当地法律
```

**授权文件必须包含**:
- 测试目标 (IP 地址、域名、系统)
- 测试时间范围
- 测试方法和深度
- 紧急联系人
- 数据处理方式

```bash
# WHOIS 查询

# DNS 记录查询

# 子域名枚举 (被动)
# 使用在线工具
# - crt.sh (证书透明度日志)
# - DNSdumpster

# 使用 Sublist3r
```

**3.1.2 搜索引擎侦察**

```bash
# Google Dork 示例
```

### 3.2 主动信息收集

**目标**: 直接与目标系统交互收集信息

**3.2.1 主机发现**

```bash
# Ping 扫描
nmap -sn 192.168.1.0/24 -oA scan/host_discovery

# ARP 扫描 (局域网)
sudo netdiscover -r 192.168.1.0/24
sudo arp-scan -l

# Masscan 快速扫描
sudo masscan -p1-65535 192.168.1.0/24 --rate=1000 -oL scan/masscan.txt
```


**3.2.2 端口扫描**

```bash
# 快速扫描常用端口
nmap -F 192.168.1.100 -oA scan/quick_scan

# 全端口扫描
nmap -p- 192.168.1.100 -oA scan/full_scan

# 服务版本探测
nmap -sV -p 22,80,443,3306 192.168.1.100 -oA scan/service_scan

# 操作系统探测
sudo nmap -O 192.168.1.100 -oA scan/os_scan

# 综合扫描 (推荐)
sudo nmap -sS -sV -O -A -p- --script=default,vuln \
    192.168.1.100 -oA scan/comprehensive_scan

# 躲避防火墙
nmap -f -D RND:10 -T2 192.168.1.100  # 分片 + 诱饵 + 慢速
```

**3.2.3 服务枚举**

```bash
# HTTP/HTTPS 服务
# 使用 Nikto
nikto -h http://192.168.1.100 -o scan/nikto.txt

# 使用 WhatWeb
whatweb http://192.168.1.100 -v -a 3 > scan/whatweb.txt

# 目录爆破
gobuster dir -u http://192.168.1.100 \
    -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt \
    -x php,html,txt,bak \
    -o scan/gobuster.txt

# 使用 ffuf (更快)
ffuf -u http://192.168.1.100/FUZZ \
    -w /usr/share/wordlists/dirb/common.txt \
    -mc 200,301,302,403 \
    -o scan/ffuf.json

# SMB 服务枚举
enum4linux -a 192.168.1.100 > scan/enum4linux.txt
smbclient -L //192.168.1.100 -N
nmap --script smb-enum-shares,smb-enum-users -p 445 192.168.1.100

# FTP 服务
nmap --script ftp-anon,ftp-bounce -p 21 192.168.1.100

# SSH 服务
nmap --script ssh-auth-methods,ssh-hostkey -p 22 192.168.1.100

# MySQL 服务
nmap --script mysql-info,mysql-enum -p 3306 192.168.1.100

# SNMP 枚举
snmp-check 192.168.1.100
onesixtyone -c /usr/share/doc/onesixtyone/dict.txt 192.168.1.100
```

**3.2.4 Web 应用指纹识别**

```bash
# 识别 CMS
```

### 12.6 实践中的坑

**坑 1: 测试环境与生产环境不一致**

```
问题: 在测试环境发现的漏洞,生产环境不存在

预防措施:
1. 明确测试目标是测试环境还是生产环境
2. 在报告中注明测试环境
3. 建议客户在生产环境验证
4. 不要假设两个环境完全一致
```

**坑 2: 触发安全设备告警**

```bash
# 问题: 扫描触发 IDS/IPS 告警,被封禁 IP

# 预防措施:
# 1. 提前通知客户
# 2. 将测试 IP 加入白名单
# 3. 使用慢速扫描
nmap -T2 --max-rate 100 target

# 4. 分时段测试
# 避免在业务高峰期测试

# 5. 准备备用 IP
# 使用 VPS 或代理
```

**坑 3: 意外中断业务**

```bash
# 问题: 测试导致服务崩溃或性能下降

# 预防措施:
# 1. 避免 DoS 测试
# 不要使用 --max-rate 过高的扫描

# 2. 限制并发连接
sqlmap --threads=1 --delay=2

# 3. 在非业务时间测试
# 凌晨或周末进行高风险测试

# 4. 准备回滚方案
# 测试前备份
# 准备恢复步骤

# 5. 实时监控
# 监控目标系统状态
# 发现异常立即停止
```

**坑 4: 数据泄露风险**

```bash
# 问题: 测试过程中获取的敏感数据泄露

# 预防措施:
# 1. 加密存储
gpg -c sensitive_data.txt

# 2. 最小化数据收集
# 只获取必要的数据
# 不要下载整个数据库

# 3. 安全传输
# 使用加密通道
scp -P 22 data.zip user@server:/secure/path/

# 4. 及时删除
# 测试结束后安全删除
shred -vfz -n 10 sensitive_data.txt

# 5. 访问控制
# 限制测试数据访问权限
chmod 600 sensitive_data.txt
```

本笔记涵盖了完整的渗透测试流程,从前期交互到报告编写的所有阶段:

1. **前期交互**: 明确测试范围和目标

3. **威胁建模**: 分析攻击面和攻击路径

5. **漏洞利用**: 获取系统访问权限
6. **后渗透**: 权限提升、横向移动、数据窃取
7. **报告编写**: 详细记录发现和修复建议

- 始终获得书面授权
- 详细记录所有操作
