## 1. 基础概念

### 1.1 VMware 网络架构

VMware Workstation 使用虚拟网络设备来实现虚拟机之间以及虚拟机与物理网络的通信:

- **虚拟网卡 (Virtual Network Adapter)**: 虚拟机内部的网络接口
- **虚拟交换机 (Virtual Switch)**: 连接虚拟机的虚拟网络设备
- **VMnet**: VMware 创建的虚拟网络接口

### 1.2 默认虚拟网络

VMware 默认创建三个虚拟网络:

| 虚拟网络 | 模式 | 用途 | 默认网段 |
|---------|------|------|---------|
| VMnet0 | 桥接模式 | 直接连接物理网络 | 与物理网络相同 |
| VMnet1 | 仅主机模式 | 虚拟机与主机通信 | 192.168.137.0/24 |
| VMnet8 | NAT 模式 | 通过主机 NAT 上网 | 192.168.80.0/24 |

### 1.3 网络模式对比


| 特性 | 桥接模式 | NAT 模式 | 仅主机模式 |
|------|---------|---------|-----------|
| 虚拟机访问外网 | ✅ | ✅ | ❌ |
| 外网访问虚拟机 | ✅ | ❌ (需端口转发) | ❌ |
| 虚拟机互访 | ✅ | ✅ | ✅ |
| 主机访问虚拟机 | ✅ | ✅ | ✅ |
| 独立 IP | ✅ | ❌ | ❌ |
| 隔离性 | 低 | 中 | 高 |
| 适用场景 | 服务器部署 | 日常使用 | 隔离测试 |

## 2. 网络模式详解

### 2.1 桥接模式 (Bridged)

**工作原理**: 虚拟机直接连接到物理网络,就像一台独立的物理机

```
物理网络 (192.168.1.0/24)
    |
    ├── 物理主机 (192.168.1.100)
    ├── 虚拟机1 (192.168.1.101)
    └── 虚拟机2 (192.168.1.102)
```

**优点**:
- 虚拟机获得独立 IP 地址
- 网络性能最佳
- 可被外部网络直接访问

**缺点**:
- 需要足够的 IP 地址
- 安全性较低
- 依赖物理网络环境

**适用场景**:
- 搭建对外服务器
- 需要外部访问的 Web 应用
- 模拟真实网络环境

### 2.2 NAT 模式 (Network Address Translation)

**工作原理**: 虚拟机通过主机的 NAT 服务访问外网

```
外部网络
    |
物理主机 (192.168.1.100)
    |
VMnet8 (192.168.80.1) - NAT 网关
    |
    ├── 虚拟机1 (192.168.80.128)
    └── 虚拟机2 (192.168.80.129)
```


**优点**:
- 不占用物理网络 IP
- 虚拟机可以上网
- 相对安全(外部无法直接访问)

**缺点**:
- 外部无法直接访问虚拟机
- 需要配置端口转发
- 网络性能略低于桥接

**适用场景**:
- 日常开发测试
- IP 地址受限环境
- 需要网络隔离的场景

### 2.3 仅主机模式 (Host-Only)

**工作原理**: 创建一个完全隔离的虚拟网络,只有主机和虚拟机可以通信

```
物理主机
    |
VMnet1 (192.168.137.1)
    |
    ├── 虚拟机1 (192.168.137.128)
    └── 虚拟机2 (192.168.137.129)
    
(无法访问外部网络)
```

**优点**:
- 完全隔离,最安全
- 不受物理网络影响
- 适合离线测试

**缺点**:
- 虚拟机无法上网
- 无法被外部访问

**适用场景**:
- 恶意软件分析
- 隔离的渗透测试环境
- 不需要联网的开发

### 2.4 自定义网络 (Custom)

可以创建自定义的 VMnet 网络,灵活配置网络拓扑

## 3. 桥接模式配置

### 3.1 图形界面配置

**步骤 1**: 选择虚拟机 → 编辑虚拟机设置

**步骤 2**: 选择网络适配器 → 桥接模式


```
虚拟机设置
  └── 硬件
      └── 网络适配器
          ├── ☑ 桥接模式
          ├── ☑ 复制物理网络连接状态
          └── 桥接到: 自动 / 指定网卡
```

**步骤 3**: 选择桥接的物理网卡

- **自动**: VMware 自动选择(推荐)
- **指定网卡**: 手动选择物理网卡(多网卡环境)

### 3.2 Linux 虚拟机配置 (Ubuntu/Debian)

#### 使用 DHCP 自动获取 IP

编辑网络配置文件:

```bash
# Ubuntu 18.04+ (使用 Netplan)
sudo nano /etc/netplan/01-netcfg.yaml
```

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    ens33:  # 网卡名称,使用 ip a 查看
      dhcp4: true
      dhcp6: false
```

应用配置:

```bash
sudo netplan apply
```

#### 配置静态 IP

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    ens33:
      dhcp4: false
      addresses:
        - 192.168.1.150/24  # 虚拟机 IP/子网掩码
      gateway4: 192.168.1.1  # 网关(路由器 IP)
      nameservers:
        addresses:
          - 8.8.8.8
          - 114.114.114.114
```

应用并测试:

```bash
sudo netplan apply
ip addr show ens33
ping -c 4 8.8.8.8
```

### 3.3 CentOS/RHEL 配置


#### DHCP 配置

```bash
# 编辑网卡配置
sudo vi /etc/sysconfig/network-scripts/ifcfg-ens33
```

```ini
TYPE=Ethernet
BOOTPROTO=dhcp
NAME=ens33
DEVICE=ens33
ONBOOT=yes
```

#### 静态 IP 配置

```ini
TYPE=Ethernet
BOOTPROTO=static
NAME=ens33
DEVICE=ens33
ONBOOT=yes
IPADDR=192.168.1.150
NETMASK=255.255.255.0
GATEWAY=192.168.1.1
DNS1=8.8.8.8
DNS2=114.114.114.114
```

重启网络服务:

```bash
# CentOS 7
sudo systemctl restart network

# CentOS 8+
sudo nmcli connection reload
sudo nmcli connection up ens33
```

### 3.4 Windows 虚拟机配置

**图形界面配置**:

1. 控制面板 → 网络和共享中心 → 更改适配器设置
2. 右键以太网 → 属性 → Internet 协议版本 4 (TCP/IPv4)
3. 配置 IP 地址

**PowerShell 配置**:

```powershell
# 查看网卡信息
Get-NetAdapter

# 配置静态 IP
New-NetIPAddress -InterfaceAlias "以太网" -IPAddress 192.168.1.150 -PrefixLength 24 -DefaultGateway 192.168.1.1

# 配置 DNS
Set-DnsClientServerAddress -InterfaceAlias "以太网" -ServerAddresses ("8.8.8.8","114.114.114.114")
```

## 4. NAT 模式配置

### 4.1 VMware NAT 设置

**编辑虚拟网络**:


1. 编辑 → 虚拟网络编辑器 (需要管理员权限)
2. 选择 VMnet8 (NAT 模式)
3. 配置子网 IP 和子网掩码

```
VMnet8 配置示例:
  子网 IP: 192.168.80.0
  子网掩码: 255.255.255.0
  网关 IP: 192.168.80.2 (自动分配)
```

### 4.2 NAT 设置详解

点击 "NAT 设置" 按钮:

```
网关 IP: 192.168.80.2
DHCP 设置:
  起始 IP: 192.168.80.128
  结束 IP: 192.168.80.254
  租约时间: 1800 秒
```

### 4.3 虚拟机 NAT 配置

**虚拟机设置**:

```
网络适配器
  ├── ☑ NAT 模式
  └── NAT 设备: VMnet8
```

**Linux 虚拟机配置 (DHCP)**:

```yaml
# /etc/netplan/01-netcfg.yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    ens33:
      dhcp4: true
```

**Linux 虚拟机配置 (静态 IP)**:

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    ens33:
      dhcp4: false
      addresses:
        - 192.168.80.100/24
      gateway4: 192.168.80.2  # VMnet8 网关
      nameservers:
        addresses:
          - 192.168.80.2  # 使用 VMware NAT DNS
          - 8.8.8.8
```

应用配置:

```bash
sudo netplan apply
ping -c 4 www.baidu.com
```

### 4.4 端口转发配置

**场景**: 外部网络访问 NAT 模式下的虚拟机服务


**图形界面配置**:

1. 虚拟网络编辑器 → VMnet8 → NAT 设置
2. 点击 "添加" 按钮

```
端口转发示例:
  主机端口: 8080
  虚拟机 IP: 192.168.80.100
  虚拟机端口: 80
  描述: Web 服务器
```

**配置文件方式** (高级):

编辑 `C:\ProgramData\VMware\vmnetnat.conf`:

```ini
[incomingtcp]
# 格式: 主机端口 = 虚拟机IP:虚拟机端口
8080 = 192.168.80.100:80
2222 = 192.168.80.100:22
3306 = 192.168.80.100:3306

[incomingudp]
# UDP 端口转发
53 = 192.168.80.100:53
```

重启 VMware NAT 服务:

```powershell
# 以管理员身份运行 PowerShell
Restart-Service VMwareNATService
```

**测试端口转发**:

```bash
# 从主机访问虚拟机 Web 服务
curl http://localhost:8080

# 从外部网络访问
curl http://主机IP:8080
```

```
VMnet2 配置:
  类型: NAT

```

**场景 1**: 隔离的渗透测试环境


```
VMnet2 (仅主机) - 攻击网络
  ├── Kali Linux (172.16.100.10)

```

```
VMnet2 (NAT) - 内网区
  ├── 应用服务器 (10.10.10.10)
  └── 数据库服务器 (10.10.10.20)
```

## 7. 多网卡配置

### 7.1 添加多个网络适配器

**步骤**:

1. 虚拟机设置 → 添加 → 网络适配器
2. 配置不同的网络模式

**典型配置**:

```
网络适配器 1: NAT (VMnet8) - 用于上网
网络适配器 2: 仅主机 (VMnet1) - 用于主机通信
网络适配器 3: 自定义 (VMnet2) - 用于内部网络
```

### 7.2 Linux 多网卡配置

**查看网卡**:

```bash
ip link show
# 输出:
# 1: lo: <LOOPBACK,UP,LOWER_UP>
# 2: ens33: <BROADCAST,MULTICAST,UP,LOWER_UP>
# 3: ens34: <BROADCAST,MULTICAST,UP,LOWER_UP>
# 4: ens35: <BROADCAST,MULTICAST,UP,LOWER_UP>
```

**Netplan 多网卡配置**:

```yaml
# /etc/netplan/01-netcfg.yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    ens33:  # NAT 网卡 - 用于上网
      dhcp4: true
    ens34:  # 仅主机网卡 - 用于主机通信
      dhcp4: false
      addresses:
        - 192.168.137.100/24
    ens35:  # 自定义网卡 - 用于内部网络
      dhcp4: false
      addresses:
        - 10.10.10.100/24
```


**配置路由**:

```bash
# 查看路由表
ip route show

# 添加静态路由
sudo ip route add 172.16.0.0/16 via 10.10.10.1 dev ens35

# 永久路由配置 (Netplan)
```

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    ens35:
      addresses:
        - 10.10.10.100/24
      routes:
        - to: 172.16.0.0/16
          via: 10.10.10.1
```

### 7.3 Windows 多网卡配置

**PowerShell 配置**:

```powershell
# 查看网卡
Get-NetAdapter

# 配置第一块网卡 (NAT - 上网)
New-NetIPAddress -InterfaceAlias "以太网" -IPAddress 192.168.80.100 -PrefixLength 24 -DefaultGateway 192.168.80.2
Set-DnsClientServerAddress -InterfaceAlias "以太网" -ServerAddresses ("8.8.8.8")

# 配置第二块网卡 (仅主机)
New-NetIPAddress -InterfaceAlias "以太网 2" -IPAddress 192.168.137.100 -PrefixLength 24

# 配置第三块网卡 (自定义)
New-NetIPAddress -InterfaceAlias "以太网 3" -IPAddress 10.10.10.100 -PrefixLength 24
```

**设置网卡优先级**:

```powershell
# 查看接口跃点数
Get-NetIPInterface

# 设置接口跃点数 (数值越小优先级越高)
Set-NetIPInterface -InterfaceAlias "以太网" -InterfaceMetric 10
Set-NetIPInterface -InterfaceAlias "以太网 2" -InterfaceMetric 20
```

## 8. 静态 IP 配置

### 8.1 规划 IP 地址

**IP 地址规划原则**:


```
网络分段:
  192.168.80.1-50    : 保留 (网关、DNS 等)
  192.168.80.51-100  : 服务器
  192.168.80.101-200 : 工作站
  192.168.80.201-254 : DHCP 动态分配
```

**示例规划表**:

| 主机 | IP 地址 | 用途 |
|------|---------|------|
| 网关 | 192.168.80.2 | VMware NAT 网关 |
| Kali Linux | 192.168.80.10 | 渗透测试主机 |
| Metasploitable | 192.168.80.20 | 靶机 |
| DVWA | 192.168.80.21 | Web 靶机 |
| Windows Server | 192.168.80.30 | 域控制器 |

### 8.2 Ubuntu/Debian 静态 IP

**完整配置示例**:

```yaml
# /etc/netplan/01-netcfg.yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    ens33:
      dhcp4: false
      dhcp6: false
      addresses:
        - 192.168.80.100/24
      gateway4: 192.168.80.2
      nameservers:
        addresses:
          - 8.8.8.8
          - 114.114.114.114
        search:
          - localdomain
```

**应用并验证**:

```bash
# 应用配置
sudo netplan apply

# 验证 IP 地址
ip addr show ens33

# 验证网关
ip route show

# 验证 DNS
cat /etc/resolv.conf

# 测试连通性
ping -c 4 192.168.80.2  # ping 网关
ping -c 4 8.8.8.8       # ping 外网
ping -c 4 www.baidu.com # 测试 DNS
```

### 8.3 CentOS/RHEL 静态 IP

**完整配置**:

```bash
sudo vi /etc/sysconfig/network-scripts/ifcfg-ens33
```

```ini
TYPE=Ethernet
PROXY_METHOD=none
BROWSER_ONLY=no
BOOTPROTO=static
DEFROUTE=yes
IPV4_FAILURE_FATAL=no
IPV6INIT=no
NAME=ens33
DEVICE=ens33
ONBOOT=yes
IPADDR=192.168.80.100
PREFIX=24
GATEWAY=192.168.80.2
DNS1=8.8.8.8
DNS2=114.114.114.114
```


**重启网络**:

```bash
# CentOS 7
sudo systemctl restart network
sudo systemctl status network

# CentOS 8+
sudo nmcli connection reload
sudo nmcli connection down ens33
sudo nmcli connection up ens33

# 验证配置
ip addr show ens33
nmcli device show ens33
```

### 8.4 Kali Linux 静态 IP

**方法 1: 使用 NetworkManager**

```bash
# 图形界面
nm-connection-editor

# 命令行
sudo nmcli connection modify "Wired connection 1" \
  ipv4.method manual \
  ipv4.addresses 192.168.80.10/24 \
  ipv4.gateway 192.168.80.2 \
  ipv4.dns "8.8.8.8,114.114.114.114"

sudo nmcli connection up "Wired connection 1"
```

**方法 2: 编辑配置文件**

```bash
sudo nano /etc/network/interfaces
```

```ini
auto eth0
iface eth0 inet static
    address 192.168.80.10
    netmask 255.255.255.0
    gateway 192.168.80.2
    dns-nameservers 8.8.8.8 114.114.114.114
```

```bash
sudo systemctl restart networking
```

## 9. 网络故障排查

### 9.1 诊断工具

**基础网络诊断**:

```bash
# 查看网卡状态
ip link show
ip addr show

# 查看路由表
ip route show
route -n

# 查看 DNS 配置
cat /etc/resolv.conf

# 测试连通性
ping -c 4 192.168.80.2  # 测试网关
ping -c 4 8.8.8.8       # 测试外网
ping -c 4 www.baidu.com # 测试 DNS

# 追踪路由
traceroute 8.8.8.8
mtr 8.8.8.8

# 查看端口监听
netstat -tuln
ss -tuln

# DNS 查询
nslookup www.baidu.com
dig www.baidu.com
```


**Windows 诊断工具**:

```powershell
# 查看网卡配置
ipconfig /all
Get-NetIPConfiguration

# 查看路由表
route print
Get-NetRoute

# 测试连通性
ping 192.168.80.2
Test-Connection -ComputerName 8.8.8.8 -Count 4

# 追踪路由
tracert 8.8.8.8

# 查看端口
netstat -ano
```

## 12. 常见错误与解决方案

### 12.1 网卡无法启动

**错误现象**:

```
Error: Connection activation failed: No suitable device found
```

**原因分析**:
- 网卡名称不匹配
- 网卡驱动未加载
- MAC 地址冲突

**解决方案**:

```bash
# 查看实际网卡名称
ip link show

# 修改配置文件中的网卡名称
sudo nano /etc/netplan/01-netcfg.yaml
# 将 ens33 改为实际网卡名称

# 重新加载网卡驱动
sudo modprobe vmxnet3
sudo modprobe e1000

# 重启网络服务
sudo netplan apply
```

### 12.2 DHCP 无法获取 IP

**错误现象**:

```bash
ip addr show ens33
# 没有显示 IP 地址,只有 link/ether
```

**原因分析**:
- VMware DHCP 服务未启动
- 网卡未启用
- DHCP 配置错误

**解决方案**:

```bash
# 方案 1: 手动获取 DHCP
sudo dhclient -v ens33

# 方案 2: 重启网络服务
sudo systemctl restart systemd-networkd

# 方案 3: 检查网卡是否启用
sudo ip link set ens33 up

# 方案 4: 检查 Windows 主机 VMware DHCP 服务
# 服务 → VMware DHCP Service → 启动
```

**Windows 主机检查**:

```powershell
# 检查 DHCP 服务状态
Get-Service VMwareDHCPService

# 启动服务
Start-Service VMwareDHCPService

# 重启服务
Restart-Service VMwareDHCPService
```

### 12.3 NAT 模式无法上网

**错误现象**:

```bash
ping 192.168.80.2  # 网关可以 ping 通
ping 8.8.8.8       # 外网无法 ping 通
```

**原因分析**:
- VMware NAT 服务未启动
- DNS 配置错误
- 防火墙阻止

**解决方案**:

```bash
# 方案 1: 检查 DNS 配置
cat /etc/resolv.conf
# 应该包含: nameserver 192.168.80.2

# 方案 2: 手动配置 DNS
sudo nano /etc/resolv.conf
```

```
nameserver 8.8.8.8
nameserver 114.114.114.114
```

```bash
# 方案 3: 检查路由
ip route show
# 应该有默认路由: default via 192.168.80.2

# 方案 4: 添加默认路由
sudo ip route add default via 192.168.80.2
```

**Windows 主机检查**:

```powershell
# 检查 NAT 服务
Get-Service VMwareNATService

# 重启 NAT 服务
Restart-Service VMwareNATService

# 检查 Windows 防火墙
Get-NetFirewallProfile | Select-Object Name, Enabled

# 临时关闭防火墙测试
Set-NetFirewallProfile -Profile Domain,Public,Private -Enabled False
```

### 12.4 桥接模式无法获取 IP

**错误现象**:
虚拟机在桥接模式下无法获取 IP 地址

**原因分析**:
- 物理网卡选择错误
- 路由器 DHCP 地址池已满
- MAC 地址被过滤

**解决方案**:

```bash
# 方案 1: 手动指定桥接网卡
# 虚拟机设置 → 网络适配器 → 桥接模式
# 桥接到: 选择正确的物理网卡 (不要选自动)

# 方案 2: 配置静态 IP
sudo nano /etc/netplan/01-netcfg.yaml
```

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    ens33:
      dhcp4: false
      addresses:
        - 192.168.1.150/24  # 使用物理网络的网段
      gateway4: 192.168.1.1  # 物理路由器 IP
      nameservers:
        addresses:
          - 8.8.8.8
```

```bash
# 方案 3: 重新生成 MAC 地址
# 虚拟机设置 → 网络适配器 → 高级 → 生成新 MAC 地址
```

### 12.5 虚拟机之间无法通信

**错误现象**:
同一网络的虚拟机无法 ping 通

**原因分析**:
- 防火墙阻止
- 网络模式不同
- IP 地址不在同一网段

**解决方案**:

```bash
# 方案 1: 检查防火墙
sudo ufw status
sudo ufw disable  # 临时关闭测试

# 方案 2: 检查 IP 地址和网段
ip addr show
# 确保两台虚拟机在同一网段

# 方案 3: 检查网络模式
# 确保两台虚拟机使用相同的 VMnet

# 方案 4: 允许 ICMP (ping)
sudo iptables -A INPUT -p icmp -j ACCEPT
```

### 12.6 端口转发不生效

**错误现象**:
配置了 NAT 端口转发,但外部无法访问

**原因分析**:
- 虚拟机防火墙阻止
- 主机防火墙阻止
- 服务未启动
- NAT 服务未重启

**解决方案**:

```bash
# 方案 1: 检查虚拟机服务是否运行
sudo netstat -tuln | grep 80
sudo systemctl status apache2

# 方案 2: 虚拟机防火墙放行
sudo ufw allow 80/tcp

# 方案 3: 检查虚拟机 IP
ip addr show ens33
# 确保 IP 与端口转发配置一致
```

**Windows 主机检查**:

```powershell

netstat -ano | findstr :8080

Restart-Service VMwareNATService

# 测试端口转发
Test-NetConnection -ComputerName localhost -Port 8080
```
